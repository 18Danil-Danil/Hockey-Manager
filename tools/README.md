# Импорт и синхронизация составов ВХЛ

## Автоматическая синхронизация

GitHub Actions запускает workflow **«Синхронизация составов ВХЛ»**:

- При изменении скрипта синхронизации или справочника клубов в ветке `refactoring`.
- По расписанию еженедельно в понедельник в 04:17 UTC, когда workflow доступен в default branch GitHub.
- Вручную через `workflow_dispatch`, если запуск доступен в интерфейсе GitHub Actions.

По умолчанию загружаются все 30 клубов. Инструмент сверяет их с каталогом ВХЛ, проверяет `robots.txt`, выдерживает паузу между запросами и проверяет полноту каждого состава.

После успешной полной выгрузки GitHub Actions автоматически обновляет `data/vhl-rosters.js` в ветке `refactoring`. Этот файл подключается в `index.html`, а `data/vhl-player-import.js` проверяет и сохраняет данные в localStorage. Новые карьеры используют реальные составы автоматически; существующие сохранения не меняются.

Запуск для отдельного клуба (например, `ryazan-vdv`) предназначен только для проверки и сохраняет результат как артефакт. Он **не заменяет** общую базу в игре.

## Результаты и отчёты

1. Открой вкладку **Actions** репозитория.
2. Выбери **Синхронизация составов ВХЛ** и последний запуск.
3. В сводке запуска доступны число обработанных клубов, игроков и ошибки.
4. JSON и отчёт можно скачать в разделе **Artifacts** (хранятся 14 дней).

## Локальный запуск

Node.js 20+:

```bash
node tools/vhl-roster-sync.mjs --team all
node tools/vhl-roster-sync.mjs --team ryazan-vdv
```

## Примечания

- Экспортируется основной состав клуба; фотографии игроков не загружаются.
- Для нападающих источник даёт общую позицию «нападающий». Внутриигровое распределение по C/LW/RW выполняется эвристически.
- Рост и вес не заполняются, если их нет в таблице основного состава.
- При ошибке или неполной выгрузке новая общая база не публикуется.
- Расписание GitHub Actions выполняется только для workflow в default branch. Пока работаем только в `refactoring`, гарантированно активен запуск при изменении файлов-триггеров; для еженедельного расписания потребуется отдельно решить вопрос с default branch, не меняя `main` без согласования.
